# 켜고 끄고 들여다보기

올린 뒤에 쓰는 명령이다. 처음 세팅은 `deploy/README.md` 에 있다.

폴더 경로와 실행 사용자는 `/etc/systemd/system/blogstudio.service` 에 있다.
여기 적지 않는다 — 두 곳에 적으면 한쪽만 고쳐진다.

## 지금 도나

```bash
systemctl status blogstudio
```

`active (running)` 이면 돈다. 그것만으로는 **키가 들어갔는지 모른다.**

```bash
curl -s localhost:8004/api/health
```

```json
{"ok": true, "llm": true, "imagen": true, "search": true, ...}
```

셋 다 `true` 여야 한다. 하나라도 `false` 면 앱은 그대로 도는데 결과물이
달라진다 — `llm` 이 거짓이면 후보가 가짜 데이터로, `search` 가 거짓이면
근거가 전부 미확인으로 나간다. **오류가 안 나므로 여기서만 보인다.**

## 켜고 끄기

```bash
sudo systemctl start blogstudio       # 켠다
sudo systemctl stop blogstudio        # 끈다
sudo systemctl restart blogstudio     # 다시 띄운다
```

부팅할 때 자동으로 뜨는 것은 따로다.

```bash
sudo systemctl enable blogstudio      # 자동으로 뜨게
sudo systemctl disable blogstudio     # 안 뜨게
```

**작업 중이던 글은 다시 띄우면 사라진다.** 드래프트가 메모리에 있어서다.
사람이 쓰고 있을 때 재시작하지 않는다.

## 로그 보기

두 가지가 있고 다른 것이다.

```bash
journalctl -u blogstudio -f              # 서버 콘솔 — 뜨고 죽는 것, 예외
journalctl -u blogstudio -n 50 --no-pager
journalctl -u blogstudio --since "1 hour ago"
```

무엇을 만들었고 사람이 무엇을 골랐는지는 콘솔에 없다. 그건 줄 로그다.

```bash
curl -s 'localhost:8004/api/logs?limit=20'
curl -s 'localhost:8004/api/logs?kind=failed'      # 실패한 것만
curl -s 'localhost:8004/api/logs?step=check'       # 원문 대조 결과
```

전체 사용법은 루트 `README.md` 의 "로그를 눈으로 볼 때" 에 있다.

## 고친 것이 반영됐나

**프롬프트(`.md`)는 다시 띄우지 않아도 된다.** 파일이 바뀌면 다음 호출부터
반영된다. `prompt.py` 가 수정 시각을 본다.

**파이썬 코드는 다시 띄워야 한다.**

```bash
sudo systemctl restart blogstudio
curl -s localhost:8004/api/health | grep -o '"code":"[^"]*"'
```

`code` 는 소스 내용의 지문이다. 파일을 바꿨는데 이 값이 그대로면 코드가
안 바뀐 게 아니라 **서버가 옛 코드를 들고 있는 것**이다. `content` 는
프롬프트와 프론트 지문이라 따로 움직인다.

## 안 뜰 때

```bash
journalctl -u blogstudio -n 50 --no-pager
```

자주 나오는 셋이다.

| 로그에 보이는 것 | 무엇 |
|---|---|
| `Address already in use` | 옛 프로세스가 포트를 물고 있다 |
| `[!] OPENAI_API_KEY 가 없습니다` | `.env` 를 못 읽었다 |
| `ModuleNotFoundError` | `.venv` 에 패키지가 없다 |

포트를 누가 물고 있는지 본다.

```bash
sudo ss -ltnp | grep 8004
```

`.venv` 는 유닛의 `ExecStart` 가 가리키는 것을 쓴다. `pip install` 을
할 때 그 `.venv` 를 켜고 해야 한다.

```bash
cd "$(systemctl show blogstudio -p WorkingDirectory --value)"
source .venv/bin/activate
pip install -r requirements.txt
```

**계속 죽으면 systemd 가 멈춘다.** 2분에 5번까지만 다시 띄운다 — 무한
재시작은 원인을 가리고 로그만 불린다. 그때는 `reset-failed` 뒤에 켠다.

```bash
sudo systemctl reset-failed blogstudio
sudo systemctl start blogstudio
```

## 유닛 파일을 고쳤을 때

```bash
sudo systemctl daemon-reload
sudo systemctl restart blogstudio
```

`daemon-reload` 를 빼먹으면 옛 설정으로 뜬다. 오류가 안 나므로 눈치채기
어렵다.
